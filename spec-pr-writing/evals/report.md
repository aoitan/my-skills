# 仕様書・PR向けスキルの比較結果

実施日: 2026-11-19。対象スキル: [spec-pr-writing](../SKILL.md)。

## 結果

スキルを作成し、自動選択を許可する設定にした。同じ6依頼を各条件で2回処理し、24出力を比較した。

**今回確認できた効果は、必要情報を保ったまま文章量と重複を減らすこと。依頼の復唱・作業宣言・不要な先回りの削減効果には差が出なかった。** スキルなしの出力も、その3種類をすでに除いていたためである。

| 観点 | スキルなし・12出力 | スキルあり・12出力 |
| --- | ---: | ---: |
| ユーザー指示のオウム返し | 0件 | 0件 |
| 作業宣言としてのガードレール | 0件 | 0件 |
| 根拠のない先回り・追加提案 | 0件 | 0件 |
| 必要情報の脱落・意味の変更 | 0件 | 0件 |
| 資料にない事実の断定 | 0件 | 0件 |
| 本文の文字数合計 | 4,073字 | 3,072字 |

文字数は合計で24.6%減った。空白と表示用のwritingブロックの囲みを除くUnicode文字数で、Markdown記号は含む。短さだけを品質評価には使っていない。

条件名を伏せたAI判定では、12組中3組でスキルありがわずかに読みやすいとされ、9組は同等だった。スキルなしが選ばれた組は0。プライマリも全出力と元資料、判定理由を照合し、今回の判定に異議はなかった。人間による評価ではない。

## 何が変わったか

| ケース | スキルなしの字数 | スキルありの字数 | 観察 |
| --- | ---: | ---: | --- |
| 検索条件保存の仕様を推敲 | 1,057 | 639 | 保存内容・再適用・保持の繰り返しが減った。2反復ともスキルありを選好。 |
| 二重送信修正のPRを推敲 | 437 | 388 | 両条件とも会話上の宣言と未来の提案を削除。読みやすさは同等。 |
| CSV仕様を新規作成 | 966 | 643 | スキルなしの1回目は本文に続いて同内容の受入条件を追加。スキルありは条件を一度ずつ記述。 |
| 通知設定修正のPRを新規作成 | 520 | 430 | スキルありは短い段落を使った。両条件とも確認事項を保持。 |
| 削除仕様の条件を保持 | 546 | 501 | 所有者限定、403/409、空白の扱い、復元不可、365日保持、未決事項を両条件で保持。 |
| 再試行PRのテンプレートを保持 | 547 | 471 | 指定の5見出し、合意済み対象外、未実施テスト、既知不具合、次PR予定を両条件で保持。 |

字数はケースごとに2反復の合計。

たとえば、二重送信PRの原稿にあった「勝手にリファクタリングを広げず、安全なガードレールを置きます」は両条件で消えた。一方で「サーバー側の重複排除は変更していないため、別タブからの同時送信は防げない」は残った。この区別は、スキルありの2反復ともできている。

## スキルの範囲

- 仕様書・PR説明文を作成または推敲する場面に限定する。通常会話、進捗報告、コードレビュー自体は対象外。
- 読み手の実装・検証・採否判断に不要な、依頼への返事、指示の復唱、書き手の作業宣言を除く。
- 要件、権限、否定・例外条件、実際の変更範囲、数値、検証範囲、未確認事項を保つ。
- 既存テンプレートやユーザー指定の構造を優先し、固定の見出しを強制しない。
- yomiyasuの意味保持の考え方を参考に、独自の短い指示として作成した。yomiyasu本体や付属の検査ツールを取り込んではいない。

## 実験方法と限界

入力と判定基準を生成前に固定した。生成担当には必要情報の正解表や採点基準を渡していない。スキル本体は生成開始から終了まで変更していない。2回の比較のA/B割り当てはseed 20261119で決め、別コンテキストの判定担当から条件名を隠した。

- 6件の合成題材、各2反復という小さな実験である。一般的な効果を証明しない。
- 両条件とも同じ既定モデル・共通システム指示を使う。共通の文体指示が既に簡潔化へ作用しており、標準状態で問題が出にくかった可能性がある。完全な無指示モデルとの比較ではない。
- 1反復の6依頼は同じエージェント内で処理した。24出力を統計的に完全独立な標本とは扱わない。
- 正確なモデル識別子・推論内部設定・生成seedは取得できない。モデルやreasoning effortの上書きはしていない。
- 2件の推敲ケースには削りたい文章をあらかじめ混ぜた。新規作成と保持確認の4件も含めたが、実際のリポジトリの文脈は再現していない。
- 生成品質はスキルを明示的に読ませて比較した。自動呼び出しの設定と通常配置先からの到達は確認したが、通常チャットでの自動発動率・誤発動率は未測定。

**判断:** 小さな補助スキルとして試す状態にはできた。今回の結果を根拠に、不要な先回りや指示の復唱が標準状態より減ると主張することはできない。実際に問題が出た仕様書・PRが得られたときは、その原文を追加して比較する価値がある。現時点では指示をさらに増やさない。

## 確認した項目

- `quick_validate.py` によるスキル形式の検査に合格。
- UIメタデータのYAMLと自動選択設定を確認。
- `~/.agents/skills/spec-pr-writing` と `~/.codex/skills/spec-pr-writing` は、このリポジトリのスキルを指している。
- `.gitignore` に自作スキルとして追加し、ツール管理スキルの除外は維持。
- 6ケース×2条件×2反復のファイルがすべて存在し、判定と対応付けが一致。生成したスキルと各出力のSHA-256を照合。
