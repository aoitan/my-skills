# 比較実験の手順

実施日: 2026-11-19（Asia/Tokyo）。依頼に基づく探索実験。

## 入力と条件

- 入力は `cases.json` の合成した6依頼。すべて出力前に固定した。
- 観点と必要情報は `rubric.md` と `invariants.json` に事前記録した。生成担当には渡さない。
- 条件は追加文章スキルなし（control）と、`spec-pr-writing/SKILL.md` を読んで適用（skill）。両条件とも既定のシステム指示は受ける。
- それぞれ2回、新規コンテキストのdefaultエージェントで6依頼を処理する。モデル・reasoning effortの上書きは行わず、親の既定を継承する。正確なモデル識別子、サンプリングseedは取得できない。
- 6依頼は1反復につき同じエージェント内で処理するため、各出力が統計的に完全独立な24サンプルという扱いはしない。
- 生成担当は他条件の結果や評価基準を読まない。後から良い結果だけを選ばず、各回の全出力を保存する。

## 生成担当への共通依頼

「文章作成の評価用に、6件の独立した依頼を処理してください。{条件説明} 読んでよい入力ファイルは {casesへの絶対パス}{skill条件のみSKILL.mdへの絶対パス} だけです。他のスキル、評価基準、報告、出力は読まないでください。cases.jsonの各requestをそれぞれユーザーからの文章作成依頼として扱い、通常その依頼に返す回答全文を、{出力ディレクトリ}/<id>.md に保存してください。ケースごとに原稿が異なるので互いの内容を混ぜないでください。依頼にない追加の文章方針・字数・見出しの制約はありません。入力は合成した題材なので、ネット検索や実装作業・外部操作は不要です。最後は作成した6ファイルの一覧だけを報告してください。」

control条件説明: 「条件として追加の文章スキルは使わず、通常の文章作成能力で回答します。」

skill条件説明: 「条件として指定のspec-pr-writing/SKILL.mdを読み、そのスキルを適用して回答します。」

実際の依頼には読み取り・書き込みツールの利用案内も付けた。成果物の書式を指定する追加制約は入れない。

## 判定

- ケース・反復ごとに両出力をA/Bへ割り当て、条件名と出力パスを外した入力を作る。条件との対応は別ファイルに保持する。
- 生成と別の新規コンテキストの判定担当に、依頼・出力・判定基準・必要情報を渡す。スキル本体や条件対応は渡さない。
- 不要な依頼復唱、作業宣言、先回り、必要情報の脱落・変更、根拠のない断定を引用と理由で記録する。
- プライマリが原文・判定・出力を照合し、機械的な文字数とは分けて結論をまとめる。

## 検証範囲

明示的に読ませたスキルの出力品質を比較する実験である。自動選択の許可設定と通常配置先からのファイル到達は確認するが、実際の通常チャットでの自動発動率、別モデルでの再現性、長大な実リポジトリでの効果はこの比較だけでは分からない。
