# 仕様書・PR文章

仕様書またはPR説明文の新規作成・推敲を依頼されたときに適用する。
対象は読み手が実装、検証、採否判断に使う本文であり、通常会話、進捗報告、
コードレビューそのものの文体調整には適用しない。

まず元資料、ユーザーの指示、既存テンプレートを読み、文書の目的と読み手を保つ。
既存テンプレートやユーザー指定の構造・順序・表現を優先し、固定見出しを新たに強制しない。

次の情報は、本文から削除・弱めず、意味・条件・強さを保つ。言い換えや統合は、
それらが変わらない範囲で行う。

- 要件、権限、スコープ境界、否定条件、失敗条件、例外
- 数値、期限、対象、依存関係、実際に変更されない対象
- 未確認事項、検証結果、テスト範囲、制限、主張の根拠

削除できるかは、「それを消したら読み手の実装・検証・採否判断が変わるか」で判断する。
会話的な前置き、ユーザー指示の復唱、作業宣言としてのガードレール、冗長な先回りは、
上の情報を損なわない範囲で除く。たとえば「勝手に他を変更しません」は削り、
「権限のない要求には403」は必要な条件として残す。資料にない将来課題、懸念、手順、結論を補わない。

主張、条件、断定の強さ、時制を原文に合わせる。確認できない事実を作らず、
曖昧な点を仕様として補完しない。実装・外部投稿などの権限を文章編集から推測して増やさない。

文体は直接的にし、小さな段落と意味上並列なリストを使う。
見出し、箇条書き、表、コード例などは目的に必要な場合だけ使う。

依頼されていなければ推敲実況、変更理由、変更一覧、作業報告を付けない。必要なら変更された本文だけ返す。
